# 开发与发布

## 模块

- `core.py`：扫描、参数验证、筛选与排片、任务身份、源文件检查。
- `render.py`：整数帧时间轴、保留重复帧节奏的预读取、缩放裁切/补边、编码与拼接。
- `jobs.py`：分段续跑、任务锁、最终验证、缓存清理。
- `__main__.py`：命令行入口。

项目不依赖 Python 第三方运行库。编码调用外部 FFmpeg/ffprobe，并使用参数数组，不通过 shell 拼接媒体文件名。
源文件路径、大小与修改时间进入任务计划；运行时文件属于本地任务数据，不应提交到仓库。
新工具的任务格式独立于旧的单次合成脚本。旧素材可重新扫描使用，旧缓存和旧排片不直接导入；更换电脑或移动素材后也应重新扫描、建立新任务。

任务 plan.json 的摘要防止意外编辑后继续混用缓存；编码代码摘要用于避免升级后复用旧段。
这不是对恶意修改本地工作目录的防护系统。工作目录应由当前用户管理，不应接收第三方提供的任务目录。

## 验证

运行 `python -m unittest discover -s tests -v`。
媒体测试需要 FFmpeg（建议9），生成的测试片段全部使用临时文件，结束后自动移除。
不要把实际素材、运行日志或测试生成的视频放到源码发布包里。

## 发布到 GitHub 前

1. 确认 LICENSE 和 README 与当前版本一致。
2. 运行完整测试；记录实际验证过的 Python、FFmpeg 和操作系统版本。
3. 检查待提交文件不含素材、成片、绝对私人路径、素材名单、凭据。
4. 确定仓库名称及公开/私有设置，再创建远程仓库。
5. 第一次发布建议标记为预览版；在 Windows 之外进行实机媒体测试后再扩展支持承诺。
